# Перенос готовых уроков без PDF

Приложение запускает подготовленные книжные уроки из `app/content/book-lessons/*.json` и проверенного `app/content/book-release.json`. Для этих уроков не нужны папка `книги/`, распознанные страницы, сканы или копии JSON в `app/studio/book-content/`. Оригинальная книга по кнопке открытия PDF будет доступна только там, где PDF установлен отдельно.

В Git должны попадать код приложения, обычные файлы `app/content/`, интерфейс `app/studio/`, готовые оригинальные уроки и release manifest. Приватные PDF, OCR, изображения страниц, профиль, диагностические файлы и ключи не добавляются. Публикация manifest сама ничего не коммитит и не отправляет в GitHub. Она также не является проверкой прав на публикацию текстов уроков: содержимое публичного изменения нужно просмотреть обычным способом.

## Создание snapshot на компьютере с приватными источниками

Из корня проекта:

```powershell
python app/scripts/publish_book_release.py --check
python app/scripts/publish_book_release.py
```

Скрипт читает каталог, все существующие канонические уроки, `app/data/parsed-books/<id>.json` и, для визуально разобранных уроков, две страницы `app/data/book-page-images/<bookId>/<page>.jpg`. Он сверяет идентификаторы, страницы, точный SHA256 исходного текста, SHA256 каждой страницы и полноту структуры урока через валидатор генератора. Ничего из исходного текста или изображений в manifest не переносится.

Отсутствующий урок остаётся неподготовленным. Если существующий урок не прошёл проверку, обычная команда заканчивается ошибкой и сохраняет предыдущий manifest. Явный `--skip-invalid` создаёт частичный snapshot только из прошедших проверку уроков; список отклонённых выводится в терминал. `--check` вообще ничего не записывает.

Опции `--content`, `--sources`, `--images`, `--output` позволяют проверять отдельную копию. После нового пакета генерации или редактирования уроков команду нужно выполнить снова. Она может прочитать snapshot во время работы генератора; готовые после этого момента уроки войдут в следующий snapshot. Для окончательного переноса проверяйте согласованную пару «уроки + manifest» после завершения пакета.

Формат версии 1:

```json
{
  "version": 1,
  "publishedAt": "2026-09-10T12:00:00+00:00",
  "total": 872,
  "ready": 1,
  "units": {
    "grammar-intermediate-003": {
      "lessonId": "book-grammar-intermediate-003",
      "bookId": "grammar-intermediate",
      "pages": [17, 18],
      "lessonSHA256": "<SHA256 полных байтов JSON урока>",
      "source": "text-layer-layout",
      "sourceHash": "<SHA256 текста приватного источника в UTF-8>",
      "visualSourceUsed": true,
      "sourceImages": [{"page": 17, "sha256": "<SHA256 JPEG>"}, {"page": 18, "sha256": "<SHA256 JPEG>"}]
    }
  }
}
```

Это пример структуры, а не текущий счётчик. Фактические `ready/total` выводит скрипт. Manifest — проверяемый артефакт репозитория, не цифровая подпись. Его доверенность определяется тем, откуда получен и как проверен сам репозиторий. Урок и manifest нужно просматривать и переносить вместе. Правило `.gitattributes` отключает преобразование концов строк в файлах уроков: даже замена LF на CRLF изменяет закреплённый SHA256.

## Проверки при запуске

Backend всегда проверяет каталог, структуру и карту учебных пунктов урока. Если приватный источник или страница присутствуют, их содержимое должно совпадать с provenance урока. Повреждённый или изменённый существующий файл нельзя скрыть подходящим manifest.

Отсутствующие приватные файлы допустимы только при совпадении полного SHA256 JSON урока и provenance с release. Поэтому изменение задания, пояснения или даже форматирования JSON требует нового snapshot на компьютере с исходниками. Уже проверенные ответы пользователя сохраняют свою версию задания.

`GET /book-content/status.json` и `GET /book-content/<id>.json` обслуживаются backend из проверенного `content`, включая метаданные заданий для планировщика. Старые статические копии не могут подменить отсутствующий или непроверенный урок. Счётчики готовности рассчитываются по реальной доступности; наличие 872 тем в каталоге не означает 872 готовых урока. Статус сборки и доступность существующей версии учитываются отдельно.

Чтобы частый опрос статуса не перечитывал всю коллекцию JPEG, кеш готовности использует размер и время изменения урока и приватных файлов, а также хеш небольшого manifest. Открытие урока и проверка ответа всегда сверяют реальные байты независимо от кеша. Первая проверка статуса выполняет полную проверку доступных уроков, последующие читают метаданные файлов.

После получения новых Go-файлов приложение необходимо пересобрать штатным способом. Уже работающий старый процесс не получит новые маршруты автоматически. `Start-English.ps1` переиспользует найденный процесс, поэтому сам по себе не обновляет его. Генерация и создание manifest не перезапускают приложение.

## Отдельные редакторские версии

С 21 сентября первые десять глав Essential Grammar in Use используют `content/book-editorial/<unitId>.json`. Это полный новый текст и упражнения, привязанные к точному SHA256 сохранённого исходного урока. Backend сначала выполняет все проверки исходника/release, затем проверяет и применяет редакцию. Сам опубликованный выпуск не переписывается; пересоздавать его ради такой редакции не нужно. В Git и при переносе приложения сохраняйте обе папки: `book-lessons` и `book-editorial`.

Редакция сохраняет якоря разделов и ID упражнений, повышает ревизии, добавляет подготовку перед заданиями. Версия книжного задания учитывает текст опоры, поэтому старый ответ не засчитывает изменённую задачу. Записи в истории остаются. Кеш доступности отслеживает и файл редакции. Неподходящий или неполный файл отклоняется; он не разрешает использовать повреждённый приватный источник. [Содержание и проверки](COURSE-EDITORIAL-2026-09-21.md).

## Аудио и дальнейшая генерация

Оригинальные записи Clear Speech хранятся отдельно от готовых текстов. Команда `python app/scripts/cache_book_recordings.py` копирует 82 проверенных MP3 из исходной папки книг в `app/data/book-recordings/`, сохраняя контрольные суммы. После этого звук работает без папки `книги/`. Для переноса сохраните эту приватную папку отдельно: Git содержит только реестр записей, а не сами MP3. Изменённая существующая копия не подменяется исходником незаметно.

Примеры и ответы сейчас озвучиваются кнопками через локальный Kokoro по актуальному тексту урока. `Start-English.cmd` запускает сервис; доступно несколько американских голосов. Старые WAV и `prepare-book-audio.ps1` сохранены как исторический способ подготовки, текущий читатель их не использует. Для чтения готовых уроков синтезатор не обязателен, для звучания нужен работающий Kokoro.

Для создания **оставшихся** уроков нужны приватные `app/data/parsed-books/`, соответствующие `app/data/book-page-images/`, генератор и настроенный доступ к используемой им модели/Codex CLI. Сами PDF нужны для повторного извлечения или рендеринга, если эти приватные промежуточные файлы утрачены. Release manifest не содержит материалы, по которым можно восстановить недостающие уроки. Страницы, полученные другим рендерером, могут иметь другой SHA256; тогда нужно повторно сверить/подготовить соответствующие уроки и выпустить snapshot.

## Регрессионные проверки

```powershell
python -m unittest discover -s app/scripts -p test_publish_book_release.py -v
Push-Location app
go test -mod=readonly ./...
$env:ENGLISH_VERIFY_BOOK_RELEASE = '1'
go test -mod=readonly ./internal/studio -run TestRepositoryBookReleaseCleanClone -count=1 -v
Remove-Item Env:ENGLISH_VERIFY_BOOK_RELEASE
Pop-Location
```

Последний тест копирует только публичные JSON в временную папку, создаёт новый сервер и проверяет каждый опубликованный урок и его доступность планировщику. Он не открывает порт, не использует реальный профиль и не копирует PDF, OCR, страницы, готовое аудио или `studio/book-content`.
