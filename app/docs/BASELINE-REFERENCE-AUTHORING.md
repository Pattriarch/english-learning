# Образцы свободных ответов старых курсов

`scripts/build_baseline_references.py` подготавливает полные иллюстративные ответы и конкретные русские разборы существующих пустых заданий. Срез до запуска: 148 уроков, 480 упражнений — 180 в `foundation.json`, 120 в `advanced.json`, 110 в `cinema-lessons.json`, 70 в `research-expansion.json`. Среди них десять `rewrite`; остальные — `write` и `speak`. Книжные и новые extended-уроки не затрагиваются.

Меняются только `answers` и `explanation` выбранного упражнения. ID, вопрос, контекст, подсказка, вид задания, теория и уже существующие ответы сохраняются. В каждом ответе один полный составной образец; две обязательные половины не записываются как альтернативы.

## Подготовка и публикация

Следующие проверки не обращаются к провайдеру:

```powershell
python app/scripts/build_baseline_references.py --dry-run
python -m unittest discover -s app/scripts -p test_build_baseline_references.py -v
```

После разрешённого запуска сначала можно подготовить три урока для редакторского просмотра, не меняя курсы:

```powershell
python app/scripts/build_baseline_references.py --limit 3 --workers 1 --batch-size 3
```

Затем опубликовать имеющиеся валидные патчи или продолжить подготовку:

```powershell
python app/scripts/build_baseline_references.py --apply-only
python app/scripts/build_baseline_references.py --resume --workers 2 --batch-size 3 --apply-ready
```

`--validate-only` повторно проверяет кеш, не публикует контент и не вызывает CLI. `--resume` принят для единообразия; повторное использование подходящего проверенного кеша включено всегда. Ограниченный запуск остаётся `partial` с ненулевым кодом завершения, пока не готовы все задания inventory. Это не сообщение об окончании всей работы. `--apply-only` не объявляет недостающие ответы готовыми.

CLI запускается без выбора модели и без переопределения reasoning; инструменты shell, unified exec и web отключены, рабочая директория временная. Пакет содержит максимум три урока. Если один результат не проходит проверку, пригодные уроки пакета сохраняются, а повторный запрос касается только оставшихся. При сообщении об исчерпании лимита очередь приостанавливается.

## Защита существующих материалов

- `data/baseline-reference-inventory.json` фиксирует исходные уроки и точные целевые ID. `sourceHash` охватывает весь исходный урок, исключая только два изменяемых поля у выбранных упражнений.
- `data/baseline-reference-patches/<lessonId>.json` содержит версию редакторского запроса, хеш источника, checksum патча, полный образец, разбор, условные допущения и сопоставление требований с ответом. Исходные значения находятся в inventory.
- Перед первым запросом и перед публикацией проверяется актуальность источника. Ручная правка вопроса, контекста, теории, подсказки, готового ответа или разбора не затирается. Допустим исходный `before` либо точно тот же уже применённый `after`.
- Все затрагиваемые файлы предварительно проверяются до записи. Каждый курс публикуется отдельной атомарной заменой; общей транзакции сразу на четыре файла нет. При внешнем изменении между проверкой и заменой работа останавливается. Повторное применение того же результата не переписывает файл.
- Кеш не является готовностью ученика. `data/baseline-reference-status.json` отдельно показывает `readyExercises` и `appliedExercises`. Процесс приложения не перезапускается; уже запущенный сервер с загрузкой базовых курсов только при старте увидит изменения после предусмотренного обновления/перезапуска.

## Границы проверки

Автоматически проверяются целевые ID и sourceHash, структура единого ответа, отсутствие шаблонных пропусков, минимум 55 русских слов объяснения, маркировка иллюстративного статуса, количественные ограничения однозначных целых ответов, нужное число вопросительных форм и происхождение выбранного исходного предложения для `rewrite`. Все десять таких заданий требуют включить реальное предложение из предоставленного авторского учебного текста, перефразировку и пояснение вместе. Повтор одного и того же разбора внутри урока/пакета отклоняется.

Подсчёт слов не доказывает точность смысла. Отдельная редакторская проверка нужна для фактических выводов, естественности языка, конкретных конструкций и объёма каждой части составного задания. Скрипт не сравнивает сумму исходного текста и короткой редакции с пределом только короткой редакции. `checks` — след проверяемых требований, составленный автором, а не независимый сертификат качества. Продолжительность устного ответа проверяется лишь широким ориентиром полноты текста, а не измерением реальной речи.

Для рассказов из жизни, прошлых ответов, выбранных пользователем записей и сцен условный образец явно называется условным. Он не свидетельствует, что кто-либо действительно услышал реплику, посмотрел эпизод, сравнил акценты или измерил улучшение. Полный вымышленный исходник включается в образец, если без него нельзя понять сокращение или редакцию. Другая история ученика допустима; фактологическая сверка опирается на его реальный источник. В киноуроках при наличии учебного текста используется именно предоставленная оригинальная ситуация, а не выдуманная реплика актёра.

## Адресные редакторские исправления

Во время очереди publisher хранит готовые патчи в памяти. Проверенные изменения уже опубликованного образца поэтому откладываются в частный `data/baseline-reference-editorial-corrections.json`, а не записываются поверх активной версии. После завершения процесса:

```powershell
python app/scripts/build_baseline_references.py --apply-only
python app/scripts/apply_baseline_reference_corrections.py --apply
python app/scripts/build_baseline_references.py --validate-only
python app/scripts/build_baseline_references.py --apply-only
```

Все четыре команды обходятся без модельных запросов. Применитель редакторских исправлений использует тот же lock, сверяет источник, checksum кэша и точные before/after, сохраняет запись правки в кэше и меняет только ответ/разбор в курсе. Все конфликты проверяются до начала записи. Записи отдельных файлов атомарны; если процесс оборвался между кэшем и курсом, сначала повторить применитель: он распознаёт обе допустимые половины и завершает ту же правку без дублирования истории. Изменение вопроса или независимая редакторская правка не принимаются за такой незавершённый запуск.

Слишком буквальная проверка источника исправлена: явно придуманный пример или сообщение «запись не предоставлена/не прослушана» не требует ещё одного конкретного прилагательного. Предпосылки всё равно обязательны. Подсчёт составных преобразований различает исходники и результат. Это изменения последующих запусков: уже работающий процесс продолжает с загруженной версией кода. Редакторские результаты и граница ручной выборки записаны в `docs/BASELINE-REFERENCE-QUALITY-2026-09-10.md`.
